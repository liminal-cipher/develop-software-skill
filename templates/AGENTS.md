# 작업 지침

이 프로젝트의 개발 작업에는 `.agents/skills/develop-software/SKILL.md`를 따른다.
작업을 시작할 때 한 번 읽는다. 컨텍스트 압축 뒤에는 이 파일과 `CURRENT_TASK.md`부터
다시 확인하고, SKILL.md는 필요한 부분만 읽는다.

## 반드시 지킬 것

1. 제공된 자료에서 필수 요구, 입출력, 예외, 제약을 먼저 추출한다. 구현을 막는
   질문만 먼저 하고, 나머지는 구현하면서 묻는다.
2. 종료 시각과 기능 동결 시각을 `CURRENT_TASK.md`에 적고, 시간은 실제 시계로 확인한다.
3. 샘플이나 가짜 데이터로라도 입력부터 결과까지 도는 첫 E2E를 먼저 만든 뒤 필수
   요구를 하나씩 채운다.
4. 모든 검사는 PASS / FAIL / NOT RUN과 근거로 보고한다. 실행하지 않은 검사를
   통과로 말하지 않는다.
5. Phase를 마칠 때와 최종 보고 전에 필수 요구 전체를 완료 관문 표로 출력한다.
6. 결과에 영향을 준 결정과 AI 제안의 채택·기각은 이유와 판단 주체를
   `DECISIONS.md`에 한 줄로 남긴다.
7. 새 세션이나 압축 뒤에는 `CURRENT_TASK.md`를 읽고 `git status`·`git diff`와
   대조한 뒤 이어간다.
8. 기능 동결 시각 이후에는 새 기능, 모델·설정 변경, 큰 리팩터링을 하지 않는다.
9. 커밋, push, 외부 전송, 환경 설정 변경은 사용자 승인 없이 하지 않는다.

## 작업 순서

요구 추출 → 첫 E2E → 요구별 구현·검증 → 완료 관문 표 → 1~2분 변경 요약 → 제출 전 점검

## 소통

사용자와는 한국어 반말로, 작업 문서는 한국어 문서체로 쓴다. 사용자가 보는 동작과
결과부터 설명하고, 이어서 처리 과정과 선택 이유를 말한다.
