# 사용자 안내

> 사람이 읽는 문서다. 에이전트 지침이 아니며, 에이전트는 이 내용을 작업 지시로
> 따르지 않는다. 시간 제한이 있는 작업에서 언제 무엇을 하고 어떤 말로 요청할지
> 정리했다. 설치 경로는 `.agents/skills/develop-software/templates/USER_GUIDE.md`다.

## 1. 설치 직후 확인

```bash
ls AGENTS.md .agents/skills/develop-software
date; TZ=KST-9 date
```

- 두 시각이 다르면 실행 환경의 시간대가 다르다는 뜻이다. 에이전트에게 시각은
  `TZ=KST-9 date`처럼 내 시간대로 보라고 말한다. `KST-9`는 "UTC보다 9시간 빠름"을
  뜻하는 POSIX 형식이라 시간대 데이터가 없는 환경에서도 동작한다. `Asia/Seoul`
  같은 이름은 그런 환경에서 조용히 UTC로 찍힐 수 있다. 내 시간대에 맞게 바꾼다.
- 커밋 기준점이 필요하면 `git init`(이미 Git이면 생략) 뒤 설치 직후 상태를 로컬에
  커밋해 둔다. 원격 저장소로 보내는 것이 막힌 환경이면 push는 하지 않는다.

필요하면 `AGENTS.md` 끝("소통" 절)에 내 상황을 알리는 줄을 덧붙인다. 해당하는
줄만 고른다.

```bash
cat >> AGENTS.md <<'EOF'
사용자는 개발 비전공자다. 기술 용어는 표와 요약 어디서든 처음 나올 때 괄호로 한 줄 풀이를 붙이고, 요약의 각 줄은 쉬운 말 한 문장을 먼저 쓴 뒤 파일·함수 이름을 근거로 붙인다. 데이터 흐름 줄은 항상 "요청이 어느 모듈과 저장소를 거치는가"를 쓴다.
웹 서버는 0.0.0.0에 띄워 개발 환경의 미리보기로 열 수 있게 한다.
EOF
tail -4 AGENTS.md
```

## 2. 시간 운영

| 시점 | 할 일 |
| --- | --- |
| 시작 15분 | 과제 설명 전체를 직접 한 번 읽는다. 담당자, 데이터, 제출물, 설명 문항을 확인한다 |
| 시작 직후 | 아래 "시작" 프롬프트. 종료 시각과 기능 동결 시각(남은 시간이 약 20%일 때)을 정한다 |
| 질문 목록이 나오면 | 골라서 담당자에게 묻는다. 답을 기다리며 멈추지 않는다 |
| 첫 E2E 요약이 나오면 | 자기 설명 질문 하나를 내 말로 답해 본다("이해 확인") |
| Phase가 끝날 때마다 | 커밋, `CURRENT_TASK.md` 갱신을 확인한다. 대화가 길면 이때만 직접 compact |
| 자리를 비울 때 | "자리 비울 때" 프롬프트. 돌아와서 `git diff`로 바뀐 것을 본다 |
| 동결 시각 | "동결" 프롬프트. 새 기능을 넣지 않는다 |
| 끝나기 25분 전 | 6절 제출 전 체크, 5절 설명 메모 |

- 같은 문제에 20분 넘게 진전이 없으면 "막혔을 때" 프롬프트로 범위를 줄인다.
- 세션은 하나로 이어간다. 자동 compact가 일어나면 "압축 뒤" 프롬프트를 보낸다.
  에이전트가 규칙을 계속 잊거나 같은 실수를 반복할 때만 새 세션을 연다.
- 큰 파일이나 긴 로그를 통째로 읽히지 않는다. "앞 20줄만", "실패한 것만 요약"처럼
  시킨다.

## 3. 프롬프트 모음

**시작**

```text
과제 설명과 데이터를 읽고, AGENTS.md와 develop-software 스킬대로 진행해 줘.
종료 시각은 __:__, 기능 동결은 __:__야. 시각은 실제 시계로 직접 확인해.
먼저 필수 요구·입출력·예외·제약과 결과를 낼 수 없는 경우를 찾고,
담당자에게 보낼 질문 목록(대상, 지금 해석, 답에 따라 바뀌는 것)을 바로 보여줘.
답을 기다리는 동안은 가정(미확인)으로 표시하고 진행해.
Phase가 끝날 때마다 무엇을 왜 바꿨는지 메시지에 적어서 로컬에 커밋해도 돼. push는 하지 마.
```

**담당자 답 전달**

```text
담당자 답변이야(__:__에 받음). 그대로 전달할게:
"..."
반영하고 DECISIONS.md에 "담당자 확인"과 받은 시각으로 남겨. 더 물어볼 게 생기면 질문으로 정리해 줘.
```

**알고리즘을 고를 때**

```text
이 결정을 코드로 옮기기 전에 DECISIONS.md에 남겨 줘.
작은 예시 하나로 입력 → 중간 판단 → 결과를 보여주고, 검토한 대안과 버린 이유를 적어 줘.
단순한 방법으로 규칙을 지키는 결과를 먼저 내고, 시간이 남으면 개선해서 같은 데이터로 비교해 줘.
```

**이해 확인**

```text
방금 요약에서 [모듈/데이터 흐름/실패 처리] 부분을 내가 이렇게 이해했어: "..."
코드 기준으로 틀린 부분만 고쳐 줘.
```

**막혔을 때**

```text
지금 20분째 진전이 없어. 현재 상태를 3줄로 요약하고, 이 기능을 더 작게 나누거나
범위에서 빼는 선택지 2개를 장단점과 함께 줘. 결정은 내가 할게.
```

**압축 뒤 또는 새 세션**

```text
AGENTS.md와 CURRENT_TASK.md를 다시 읽고 git status, git diff와 대조한 뒤
현재 상태와 다음 행동 3개만 말해 줘.
```

**자리 비울 때**

```text
지금부터 __분 동안 내가 답을 못 해. 범위·기준값·업무 규칙은 바꾸지 말고,
결정이 필요 없는 일만 해 줘: 빠진 예외 테스트 추가 → 샘플 맞춤 점검 →
문서(SYSTEM_FLOW·DECISIONS·README)를 코드와 맞추기. 끝나면 바꾼 것을 목록으로 남겨 줘.
```

**샘플 맞춤 점검**

```text
코드에 주어진 샘플 데이터에만 맞춘 부분(특정 ID·값 하드코딩, 이 데이터에서만 통하는 조건)이 있는지 찾아 줘.
값을 바꾼 데이터를 만들어 한 번 더 돌리고 결과를 PASS/FAIL로 보고해 줘.
```

**동결**

```text
지금 기능 동결 시각이야. 새 기능은 넣지 말고 완료 관문 표, README 재현 확인,
NOT RUN 항목 정리만 해 줘.
```

**설명 답 대조 (내가 먼저 쓴 다음에만)**

```text
아래는 내가 쓴 설명이야. 코드·문서와 사실이 다른 부분만 짚어 줘. 문장을 대신 써 주지는 마.
...
```

## 4. 담당자에게 묻는 요령

- 한 질문에 주제 하나. 답이 예/아니오나 값 하나로 나오게 묻는다.
- 대상 + 상황 + 내 해석을 넣는다. 넓은 질문("숨은 조건 다 알려 주세요")은 답이
  안 나온다.
- 기준을 바로 묻지 말고 기준을 정하는 데 필요한 사실을 묻는다. 실제 값을 보여 주고
  보기 2~3개와 "또는 다른 방식"을 붙인다.
- 처음에는 업무 맥락(지금 어떻게 하는지, 최근에 곤란했던 사례)도 한두 개 묻는다.
- 답이 모호하면 역제안으로 확인한다: "제가 이해한 건 ○○이라서 △△로 하려고
  합니다. 맞을까요?"
- 알고리즘·구현 방법은 묻지 않는다. 그건 내가 정한다.
- 답은 원문 그대로, 받은 시각과 함께 에이전트에게 전달한다.

## 5. 설명·서술형 답 뼈대

AI 초안을 먼저 받지 않는다. 내 말로 쓴 뒤 "설명 답 대조"로 사실만 확인한다.

| 질문 유형 | 답 순서 | 근거 위치 |
| --- | --- | --- |
| 방법 선택 | 문제 상황 → 고른 방법 → 작은 예시 → 버린 대안과 이유 → 한계 | DECISIONS.md |
| 데이터 흐름 | 누가 적고 → 어디에 남고 → 누가 읽나 | SYSTEM_FLOW.md |
| 실패 처리 | 알아채기 → 상태 변화 → 사용자 화면 → 확인 방법 → 한계 | SYSTEM_FLOW.md, 완료 관문 표 |
| 결과 없음·상한·데이터 부족 | 사용자에게 보이는 메시지 그대로 + 이유 | 화면, 테스트 |
| 가정·미구현 | 담당자 확인(시각) / 내 가정 / 미구현·NOT RUN | DECISIONS.md, PLAN.md |
| AI 활용 | 받아들인 제안과 이유, 거절한 제안과 이유, 다음 테스트 | DECISIONS.md |
| 약점·위험 | 내 코드의 구체적 약점 → 그 위험이 어디로 번지나 → 다음에 무엇을 검증·개선하나 | 완료 관문 표, 한계 |

- 메모 맨 위에 "가장 약한 곳"을 한 줄로 적는다.
- 확인한 것마다 (AI 확인)과 (내가 봄)을 구분한다. 확인하지 않은 것은 "확인하지
  못했다"고 쓴다.
- 질문에 코드와 다른 전제가 섞여 있으면 먼저 바로잡고 답한다.
- 업무 의미를 한 문장 넣는다. 무엇을 막거나 줄였는지.

## 6. 제출 전 체크

- [ ] 비밀값(키, 토큰)이 파일에 없다

- [ ] 설명 메모를 내 말로 다 썼다
