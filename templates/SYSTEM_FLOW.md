# 시스템 흐름

> 따로 실행되는 구성요소나 저장 상태가 있을 때만 만든다. 실제 코드에서 확인한 내용만 적고, 확인하지 못한 연결은 "미확인"으로 남긴다. 구조가 바뀌면 갱신한다.

- 마지막으로 코드와 대조한 시점:

## 1. 구성요소와 실행 위치

| 구성요소 | 실행 방식 | 실제 파일·함수 | 맡는 일 | 상태 |
| --- | --- | --- | --- | --- |
| [예: 웹 서버] | [별도 프로세스 / 같은 프로세스 / 예약 작업] | [경로·함수] | [요청 검사, 작업 등록 등] | 구현됨 / 테스트로 확인됨 / 미구현 / 미확인 |

## 2. 대표 요청의 경로

[사용자 동작] → [받는 함수] → [검증·변환] → [저장·작업 등록] → [처리] → [결과 저장] → [사용자에게 보이는 결과]

[각 단계에 실제 파일·함수 이름을 붙인다. 요청과 처리가 따로 실행되면 둘이 무엇으로 연결되는지(DB 상태, 큐, 파일 등)를 적는다.]

## 3. 데이터와 상태 저장

| 데이터·상태 | 저장 위치 | 쓰는 곳 | 읽는 곳 | 바뀌는 시점과 보호 방식 |
| --- | --- | --- | --- | --- |
| [예: 작업 상태] | [테이블·파일 등] | [함수] | [함수] | [트랜잭션, 잠금, 덮어쓰기 규칙 등. 없으면 없음] |

## 4. 실패 상황별 동작

| 상황 | 코드의 처리 | 남는 상태 | 복구 방법 | 사용자가 보는 메시지 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 잘못된 입력 | | | | | |
| 결과가 없음(예: 조건을 만족하는 해 없음) | | | | | |
| 처리 중 프로세스 종료 | | | | | |
| 서버 재시작 | | | | | |
| 같은 요청 반복·동시 수정 | | | | | |

해당하지 않는 행은 지운다. 구현되지 않은 복구나 재시도는 구현된 것처럼 적지 않고 "미구현"으로 둔다.
